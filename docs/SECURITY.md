# Ichido security review

Reviewed baseline `83ac5a7` and the hardening on `codex/security`. Deploy migration `20261123150000` before the matching web release. The shared development database still needs this migration. Missing quota and authorization functions cause requests to fail closed.

## Threat model

Anyone can reach the web routes, Supabase Auth, Realtime, MCP and workflow endpoints. A phone can obtain anonymous identities, change request fields and supply arbitrary text. A lost phone can retain a session and an unexpired media token. Staff members have distinct roles. Each Help Point holds a station-specific credential and allows physical provisioning. A hand-off recipient can copy a link.

The assets are private drafts, confirmed statements, staff identities and assignments, pairing codes, hand-off links, device and provider credentials, firmware signing keys, audit history, service availability and model spend. Deployment administrators, the offline firmware signer and configured identity/media providers are trusted. Revocation protects future reads. A recipient can retain an earlier copy.

## Security architecture

| Boundary | Enforcement |
|---|---|
| Staff sign-in | Better Auth (schema `auth_ba`): invite-only accounts, scrypt password hashes, 12–128 characters, breached passwords refused (k-anonymity range query), email verified by the invite link. A second factor is mandatory: TOTP (one-time use, account lockout after ten failed codes), backup codes, email codes only as a fallback, or a user-verified passkey (rpID from `PASSKEY_RP_ID`). Only a session created by a second factor is aal2, and only aal2 sessions get any permission. Sessions are httpOnly, SameSite=Lax, Secure in production, idle-expire after four hours and roll every five minutes; password change or reset revokes every other session. Per-source rate limits and per-address lockout (five failures per 15 minutes) live in the database; answers are identical for unknown addresses. A sign-in from a new device is emailed. Better Auth's own admin, sign-up, delete-user, change-email and 2FA-disable endpoints are not callable from browsers. |
| Staff database access | `/api/auth/supabase-token` mints a five-minute HS256 token (project JWT secret) for an aal2 session. `ichido.my_role()` accepts it only while that Better Auth session exists, is aal2 and its user is not disabled, so revocation, disabling and MFA reset cut PostgREST and Realtime at once. The browser keeps the token in memory; nothing is stored in localStorage. |
| Permissions | One matrix (`web/lib/rbac.ts`) for operator, field, manager, admin and auditor builds Better Auth access control and is checked by `/api/cmd` (deny by default for any command not listed), `/api/admin`, `/api/mcp` and the navigation. Account administration is written to the append-only `ichido.staff_audit`; admins cannot change, disable or reset themselves. |
| Web commands | A minted staff token, the staff session cookie (same-site requests only) or a Supabase anonymous bearer identifies the actor. The server looks up the staff role or unexpired caller binding. For staff commands, a supplied case ID selects a record and the command checks permission. Callers operate on their bound case. Guard commands check the current assignee and assignment generation. |
| PostgREST | RLS protects drafts, desk, cards, replies, jobs, device health, training and bot records. Command functions run transactions with fixed search paths and explicit grants. Schema-qualified ownership predicates protect caller data. Managers may read aggregate insights, station data and overdue-case reasons. All operators may manage legacy hand-offs. Creating a hand-off for a frontline case requires its human owner. |
| Audit and subscriptions | Case events reject direct update/delete, with a specific exception for deletion cascading from the whole case. Disaster history has its own append-only trigger. Live updates are Broadcast from the database on private topics that carry no row data (which table changed; the toast feed adds only the event id, case and reason): policies on realtime.messages admit staff to live:<table>, operators to live:feed, and a caller only to their own live:incident:<id> and live:station:<id>. Clients refetch through table RLS and never publish on live topics. Operator presence uses a private topic with separate read and publish policies on realtime.messages. Presence is advisory. [Supabase channel isolation](https://supabase.com/docs/guides/realtime/concepts) |
| Devices | Bearer secrets are station-specific. The server hashes both candidates to a fixed width and compares in constant time. A station lock, unique event ID and one-open-case index make retries idempotent. The physical display checks digest and expiry against the current pairing code. |
| Public hand-off | A 192-bit random bearer selects one case. Only its SHA-256 digest is stored. Successful access consumes a view and appends its audit event in the same transaction. The recipient projection omits caller words, teach-back text and staff names. Links expire after 24 hours and support immediate revocation. |
| Providers and workflow | OpenAI receives bounded input as data and has no command tools. Gemini's read tools are confined to one case. Suggestions are checked against current eligible replies and the guard roster. The operator makes the decision and SQL checks reply rules. Training uses separate tables. The workflow rereads case state on each wake and records recommendations, reminders and metrics. The local SDK authenticates queue callbacks before reading the envelope. The unused public webhook returns 404. Escalation cron runs inside Postgres. |
| Official feeds | `/api/cron/disaster` runs only with the `CRON_SECRET` bearer (constant-time compare; unset = refused). It fetches fixed JMA and P2PQuake HTTPS URLs (bulletin URLs only from the JMA data host) with no redirects, an 8 s timeout and a 2 MB feed / 4 MB bulletin cap. Feed content is data: fast-xml-parser with entity processing off, only fixed fields read and checked against code tables; only bounded Nagasaki area names are stored (for matching station areas) and no feed text is shown. An alert only creates a proposal; disaster mode changes only when an operator, manager or admin confirms (`cmd_disaster_proposal` → `cmd_disaster`). Alerts and proposals are readable by those roles (and auditors) only. |
| Evacuation sites | `public.shelter_site` is readable by staff only. A caller gets at most five public site names, addresses and distances for their own bound station's active hazard through the security-definer `caller_shelters()`. |
| Staff notifications | `public.push_subscription` rows are keyed to a Better Auth session (cascade on sign-out, revocation, expiry) and readable or deletable only by their owner under RLS; only `/api/cmd` (aal2 operator, guard or manager) writes them. Web endpoints must belong to a browser push service, so a subscription cannot point the server at another host. Recipients come from the database (role, owner, assignee) at delivery time, through `public.alert_subscriptions`, which also rechecks the session. Payloads are a title, a station label, a same-site link and a tag: no caller text. Better Stack heartbeat URLs must be on Better Stack's hosts. |
| Voice | Only a caller paired to an open, voice-enabled case receives a microphone-scoped join grant. Its lifetime is capped at ten minutes and at binding expiry. Signed read-backs include the room, sender, timestamp, nonce and exact text. The agent validates the envelope, bounds input and disables session recording. |
| Device voice | Only an operator on a live aal2 session can start it, and only for an open, unclaimed AI case with no caller, in a voice language. The server creates an anonymous user for the device session and binds it for 30 minutes (`binding.device`); the device fetches its grant with its station secret (`POST /api/device/voice`), the same microphone-only, ten-minute caller grant, and the agent, signing and monitor paths are the caller's own. A device press confirms only the revision just read back, and on a pack case accepts only that revision's AI suggestions (`device_accept_triage`). The spoken hand-off is delivered once per room and AI epoch (`voice_farewell`). |

## AI-first text intake

Migration `20261124060000_frontline.sql` adds the submitted-turn record. The phone reads only its current binding generation. Operators read the monitor through an audited command that rechecks their active second-factor session. Managers receive aggregate counts. Field staff and partner links have no transcript projection. Realtime carries invalidations only.

The command screens numbers before storage and model calls. A simultaneous risk signal survives withholding. A locked commit checks ownership generation, language and fact revision. An informational reply also needs an explicit autonomous manual entry and caller-confirmed facts. The first pilot entry is `SHELTER_INFO`. Consequential commands require a person. The web and firmware release depend on the matching local migration.

Vercel supplies the trusted source address. Self-hosting uses a shared source bucket. Users behind one NAT can share a quota. Edge and Auth signup limits still matter for distributed traffic. Credential-bearing CLI requests reject redirects. [Vercel request headers](https://vercel.com/docs/headers/request-headers)

## Release and verification

Apply the database migration before the web release. Rebuild native binaries, reload older presence clients, synchronize web and agent clocks, and replace firmware template trust material before deployment. The replay cache lasts for the running room job. Redact raw hand-off paths at the reverse proxy and CDN. Physically verify NVS encryption, signed OTA and rollback. See [deployment procedures](DEPLOY.md).

- Both production npm audits report zero critical and zero high advisories after hardening. Web and mobile still include moderate minimatch dependency chains. The affected consumers pin major version 10. The patched major removes APIs. Source review found no caller-supplied glob flowing into those packages. [Maintainer advisory](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249) and [breaking changes](https://github.com/isaacs/minimatch/blob/main/changelog.md)

- Reachable Git patches were searched for provider credentials, JWTs, private keys, assignments and sensitive filenames. Three credential-assignment matches were local test fixtures. Tracked environment files were examples. No production credential was identified or tested. Pattern matching cannot rule out arbitrary secrets.
- Web typecheck, lint, Japanese copy checks, production build, loopback HTTP tests, native TypeScript, agent unittests and firmware compilation passed. Hosted workflow delivery, real voice, map tiles, physical secure storage and hardware rollback await deployment or device evidence.
- The read-only Supabase guard blocked application of the migration. The version has not been registered. SQL and PL/pgSQL parsed offline. Full journey, migrated RLS and private Realtime verification remain outstanding. A quota test received 503 with the limiter absent.

### Hand-off links and case retention

A hand-off link expires after 24 hours and can be revoked sooner. Its expiry ends access to the recipient-specific report. The operator records the receiving desk's acceptance through the established service channel. Opening the link does not acknowledge the task.

Raw wording belongs to the case. Deleting the case removes its draft and teach-back through the foreign-key cascades and removes the original and translated statements stored on the desk. Operators must use the case owner's retention and deletion procedure for these records independently of link expiry. For AI-frontline cases, an hourly database job erases submitted wording and its case-local copies after seven days, including translations, draft, teach-back and summary records. Coded turns, resolution evidence and audit events remain. Infrastructure owners manage backup expiry and legacy case retention independently.

A frontline voice job signs requests against a time-limited case and caller binding. Speech verification binds the turn, locale, room and ownership generation immediately before synthesis. Operator media grants require an active two-factor operator session and are subscribe-only. Manager QA uses a separate projection that omits free text. Receipt access requires the caller’s unexpired follow-up authorization.
